context-engineering

 Problem
Two parallel SecurityProfile systems:

YAML adapters (knowledge_base/adapters/*.yaml) — rich, CWE-mapped, framework-specific
core/profiles.py — hardcoded Python, less detailed
Profiler uses YAML, Detector/Verifier use profiles.py → knowledge duplication, inconsistency.

Fix
profiles.py should load from YAML adapters as primary source, fallback to hardcoded if YAML missing.

Files
core/profiles.py
.agent/knowledge_base/adapters/*.yaml




2.Wire taint trace from Explainer into Verifier PoC generation

Problem
Explainer creates finding.taint_trace (source→sink path) but Verifier ignores it when generating PoC. LLM writes PoC without knowing exact data flow path → generic, often fails.

Fix
Pass finding.taint_trace as context to _generate_poc():

context = template_content + "\nData Flow: " + format_trace(finding.taint_trace)
Impact
Estimated +8% PoC success rate.

Files
core/agents/verifier.py — _generate_poc()

7.Add verification strategies for non-crash bugs (IDOR, timing, multi-step)
detection-quality

Problem
Verifier only checks exit_code == 0 → confirmed. Non-crash bugs need different strategies:

Race condition → timing analysis
IDOR → diff response between 2 users
Crypto weakness → statistical analysis
Business logic → multi-step workflow
Acceptance Criteria

Verification strategies: CRASH_BASED, DIFF_BASED, TIMING_BASED, MULTI_STEP

Verifier selects strategy based on CWE category

Problem

Fix

Problem

Acceptance Criteria

Phase 3 includes cross-endpoint correlation after individual analysis

Problem

11.Improve framework detection beyond file extension counting

Problem
detect_language() only counts file extensions. .py → always ("python", None). Cannot distinguish Flask/Django/FastAPI. Wrong framework → wrong SecurityProfile sources/sinks.

Fix
Check marker files: manage.py → Django, pom.xml + Spring → Spring Boot, composer.json → Laravel/Symfony, package.json → Express/Next.js.

Files
core/profiles.py — detect_language()


12.LLM cache stores source code plaintext — data protection risk

Problem
core/llm_cache.py stores full prompt_text (containing target source code) in SQLite. For pentest engagements, this violates data handling policies.

Fix
Option A: Store only prompt_hash + response, drop prompt_text
Option B: Encrypt prompt text before storage

Files
core/llm_cache.py — set() method, line ~85

16.LLMGateway locked to Antigravity — add Gemini API fallback

Problem
core/llm_gateway.py hardcodes self.provider = "antigravity". If Antigravity monitor is not running, entire pipeline hangs. New developers cannot test pipeline without Antigravity setup.

Proposed Fix
if self._check_antigravity_available():
    self.adapter = AntigravityAdapter(...)
else:
    self.adapter = GeminiDirectAdapter(api_key=os.getenv("GOOGLE_API_KEY"))
Acceptance Criteria

Pipeline works with GOOGLE_API_KEY env var (no Antigravity needed)

Antigravity still prioritized when available

Clear error message when both unavailable
Files
core/llm_gateway.py
core/adapters/ (new GeminiDirectAdapter)


17.Sandbox --network none blocks HTTP-level PoC verification

Problem
sandbox_executor.py uses --network none for all PoC execution. Web vulnerability PoCs (SQLi time-based, XSS reflected, SSRF, IDOR) need HTTP access to target app. These PoCs never verify successfully in current sandbox.

Proposed Fix
Unit-test PoC (direct function call): keep --network none
HTTP-level PoC (request to target): use Docker user-defined network, allow traffic to target container only
Add sandbox_type param: isolated vs target-only
Acceptance Criteria

PoC scripts can reach target app container

Cannot reach internet/external hosts

Configurable per-finding based on sandbox_type in prompt metadata
Files
core/tools/sandbox_executor.py
